# 周辺状況把握レポート (PWA)

日時と地点（住所または緯度経度）を入力すると、その付近の周辺状況を
**OpenAI の Web 検索** で調査・分析し、Markdown レポートとして表示するモバイル対応 Web アプリ（PWA）です。

調査する観点:

- 道路の状況（通行止め・道路の被害・渋滞）
- 断水情報 / 停電
- 斜面崩壊・土砂崩れ / 建造物被害
- 避難所情報 / 給水所 / 医療機関
- 関連する最新ニュース・事象・災害予報・SNS情報の分析

## 特徴

- **入力式**: 日時・緯度経度・住所はすべてフォームから入力します。
- **地図表示**: レポートに登場する地名を Leaflet + OpenStreetMap 上にピン表示します（地名チップのタップで地図が移動）。
- **段階表示**: レポートは「サマリー」から始まり、重要度順にセクションを設計。
  各セクションの終わりに「このあとは〇〇というセクションがありますが表示しますか？」と確認し、
  「はい」を選ぶと次のセクションを表示します。
- **事実と推定の区別**: 本文では `[事実]` / `[推定]` を明示します。
- **PWA**: ホーム画面に追加してアプリのように利用できます。

## 携帯で使う（GitHub Pages で公開）

このリポジトリはルート直下に静的ファイルが揃っているため、GitHub Pages で
そのまま公開できます。**初回のみ、リポジトリ設定で 1 回だけ有効化**が必要です。

1. GitHub のリポジトリ →**Settings** → 左メニュー **Pages** を開く
   （直リンク: `https://github.com/showg1005/ggai_reporting_4/settings/pages`）
2. **Build and deployment** の **Source** を **「Deploy from a branch」** に設定
3. **Branch** で `claude/kind-gauss-krt3ke` を選び、フォルダは **`/ (root)`** →**Save**
4. 1〜2 分待つと公開 URL が表示されます:
   **`https://showg1005.github.io/ggai_reporting_4/`**
5. スマホでこの URL を開き、ブラウザの共有メニューから
   **「ホーム画面に追加」** でアプリのように使えます（PWA）。

> 以後、このブランチに push するたび GitHub Pages が自動で再ビルドします。
> `main` などに移したい場合は、公開したいブランチを同様に指定してください。

## ローカルで試す

```bash
# 例: どれか一つ（HTTPS でなくても localhost なら動作します）
python3 -m http.server 8080
npx serve .
```

## 初回セットアップ（共通）

1. ブラウザでアプリを開き、右上の **⚙ 設定** から **OpenAI API キー** を入力して保存します。
   - キーはこの端末のブラウザ内（`localStorage`）にのみ保存され、外部サーバーには送信しません。
   - 既定モデルは `gpt-4o`（Web 検索対応モデル）。設定から変更可能です。
2. **日時** と **場所（住所 or 緯度経度）** を入力し、「レポートを作成」をタップします。

## 技術構成

| 役割 | 使用技術 |
| --- | --- |
| アプリ形態 | PWA（バニラ HTML/CSS/JS、ビルド不要） |
| レポート生成 | OpenAI Responses API（`web_search` ツール、JSON 出力）|
| 地図 | Leaflet + OpenStreetMap タイル |
| 住所→座標 / 地名→座標 | Nominatim（OpenStreetMap ジオコーディング） |
| オフライン起動 | Service Worker によるアプリシェルキャッシュ |

## 注意事項

- OpenAI API キーはブラウザから直接呼び出します。個人利用向けの構成です。
  複数ユーザーに公開する場合はキーを守るためのバックエンド・プロキシの追加を検討してください。
- Nominatim は利用規約により 1 リクエスト/秒に制限しています（地名ピンは順次追加）。
- 実際の避難・防災判断は、必ず自治体・気象庁など公式情報を確認してください。
